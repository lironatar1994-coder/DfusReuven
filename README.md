# דפוס ראובן — אתר תדמית ומכירה

אפליקציית Next.js 15 (App Router) בעברית מלאה (RTL), mobile-first.
מבנה ופריסה זהים ל-LibiDiamonds: PM2 מאחורי Nginx בכתובת `https://vee-app.co.il/DfusReuven`.

## הרצה מקומית

```bash
npm install
npm run dev
```

האתר עולה בכתובת http://localhost:3000

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח (Turbopack) |
| `npm run build` | בניית פרודקשן |
| `npm run start` | הרצת הבנייה |
| `npm run typecheck` | בדיקת טיפוסים בלבד |

## מבנה הפרויקט

```
src/app/                  עמודים (App Router)
  page.tsx                עמוד הבית
  services/               שירותים
  products/               קטלוג + [slug] לעמוד מוצר דינמי
  portfolio/              תיק עבודות
  about/ contact/ quote/  אודות, צור קשר, בקשת הצעת מחיר
  accessibility/ privacy/ terms/
  api/quote/route.ts      קבלת פניות והעלאת קבצים
  globals.css             מערכת העיצוב כולה
  robots.ts sitemap.ts    SEO
src/components/           רכיבים משותפים
src/data/catalog.ts       שירותים + מוצרים (מקור האמת לקטלוג)
src/data/content.ts       תיק עבודות, המלצות, שאלות נפוצות, נתונים
src/lib/site.ts           פרטי העסק, טלפון, וואטסאפ, כתובת
public/images/            תמונות המוצרים
legacy-static/            גרסת ה-HTML הסטטית שקדמה לפורט (מקומית בלבד)
```

**כדי לערוך תוכן** – ברוב המקרים לא נוגעים ב-JSX:

- מוצר חדש או שינוי מחיר, מידות, חומרים וגימורים → `src/data/catalog.ts`
- עבודה חדשה בתיק העבודות או המלצה → `src/data/content.ts`
- טלפון, וואטסאפ, כתובת, שעות פתיחה → `src/lib/site.ts`

הוספת מוצר ל-`catalog.ts` יוצרת אוטומטית עמוד מוצר, ערך ב-sitemap ואפשרות בבורר בטופס.

## מערכת העיצוב

הקונספט: **הדף כגיליון דפוס**.

- **פס CMYK** בעובי 3px בראש כל עמוד ובפוטר — סרגל הצבע שמדפיסים שמים בקצה גיליון.
- **כרטיסי מוצר כתעודת עבודה** — כל כרטיס נושא שורת מפרט (`350 גרם · למינציה מטית`) בספרות טבלאיות.
- **טיפוגרפיה**: Miriam Libre לכותרות (הפונט העברי החזק והמלא-דיו), Heebo לגוף הטקסט.
- **פינות 3px** ולא 20px — נייר חתוך הוא ישר. עיגול מלא נשמר רק לכפתורים.

כל הצבעים והמרווחים מוגדרים כמשתני CSS בראש `src/app/globals.css`.

## מחשבון המחירים

`src/data/pricing.ts` הוא הקובץ היחיד שצריך לעדכן כדי שהמחירים באתר יהיו אמיתיים.
הוא מגדיר לכל מוצר מדרגות כמות (טווח מחיר לכל הריצה, **לא כולל מע״מ**) ומקדמי גימור.

**המספרים שם הם דוגמה בלבד**, מבוססים על מחירונים ישראליים מפורסמים. יש להחליף אותם
במחירים של דפוס ראובן לפני העלייה לאוויר. אחרי העדכון:

- המחשבון בעמוד הבית מציג טווחים נכונים
- כרטיסי המוצר מציגים את מדרגת הפתיחה במקום placeholder
- הטווח שנבחר עובר אוטומטית לטופס הצעת המחיר

הבחירה להציג **טווחים ולא מספר מדויק** תואמת את הנוהג בשוק (ראו printfix, כרטא פרינט,
מחירון ארגון בתי הדפוס): טווח עונה על שאלת הלקוח בלי לתת למתחרה מספר לרדת ממנו, ובלי
לחייב את בית הדפוס לפני שהמפרט סופי. לצד כל טווח מופיעה הסתייגות שזו הערכה בלבד.

## בדיקת קבצים

`src/lib/artwork.ts` בודק בדפדפן, לפני השליחה, אם הקובץ שהלקוח צירף מתאים לדפוס:
קורא את מידות הפיקסלים ומחשב עד איזה גודל פיזי הוא יודפס באיכות מלאה (300dpi).

- קובץ קטן מדי → אזהרה מיידית עם הגודל המקסימלי שהוא כן מתאים לו
- קובץ בינוני → הסבר לאילו מוצרים הוא מספיק
- PDF/AI/PSD → נאמר במפורש שהבדיקה נעשית ידנית ולא מתיימרים לבדוק אוטומטית

זו הפונקציה שחוסכת הדפסות חוזרות: הלקוח יודע תוך שנייה במקום לחכות יום לתשובה מאדם.

## טופס הצעת המחיר

`POST /api/quote` מקבל `multipart/form-data`, מאמת בצד השרת ושומר:

- הפנייה מתווספת כשורה ל-`$QUOTE_STORAGE_DIR/quotes.jsonl`
- הקבצים המצורפים נשמרים ב-`$QUOTE_STORAGE_DIR/files/<id>/`

מגבלות: עד 5 קבצים, עד 25MB לקובץ, סיומות PDF/AI/PSD/EPS/JPG/PNG/TIFF/ZIP בלבד.
בנוסף יש הגבלת קצב (5 פניות ל-10 דקות לכל IP) ושדה מלכודת נגד בוטים.

**לקבלת התראה על פנייה חדשה** – הגדירו `QUOTE_WEBHOOK_URL`. כל פנייה נשלחת כ-JSON
לכתובת הזו (Zapier, Make, סלאק וכו׳). אם ה-webhook נכשל, הפנייה עדיין נשמרת לדיסק.

> כרגע לא מוגדרת שליחת מייל. עד שתחברו webhook, הדרך לראות פניות חדשות היא
> `tail -f /var/lib/dfus-reuven/quotes/quotes.jsonl` על השרת.

## דיפלוי

שני זוגות סקריפטים, בדיוק כמו ב-LibiDiamonds:

| | סטייג׳ינג | דומיין סופי |
|---|---|---|
| הרצה | `deploy.ps1` | `deploy_live.ps1` |
| בשרת | `deploy_linux.sh` | `deploy_live_linux.sh` |
| כתובת | `https://vee-app.co.il/DfusReuven` | `https://www.dfusreuven.co.il` |
| תיקייה | `/root/DfusReuven` | `/root/DfusReuven-live` |
| תהליך PM2 | `dfus-reuven` | `dfus-reuven-live` |
| פורט | `3104` | `3106` |
| אינדוקס בגוגל | חסום (`noindex`) | פתוח |
| מקור הקוד | git push ל-GitHub | ארכיון מ-HEAD, worktree נקי בלבד |
| החזרה לאחור | אין | אוטומטית לגרסה הקודמת |

שניהם שומרים פניות ב-`/var/lib/dfus-reuven/quotes` — **מחוץ** לתיקיית הריליס, כדי
שהחלפת גרסה לא תמחק פניות או קבצים של לקוחות.

### סטייג׳ינג

```bash
powershell -ExecutionPolicy Bypass -File deploy.ps1
```

typecheck ובנייה מקומית (כדי לתפוס שגיאות לפני השרת), קומיט, push ל-
`github.com/lironatar1994-coder/DfusReuven`, ואז `deploy_linux.sh` בשרת דרך SSH.
בהרצה הראשונה הסקריפט מאתחל את הריפו המקומי ומוסיף את ה-origin לבד.
אם ריפו ה-GitHub עדיין ריק, הוא נופל אוטומטית לסנכרון ישיר עם ארכיון.

### דומיין סופי

```bash
powershell -ExecutionPolicy Bypass -File deploy_live.ps1
```

דורש worktree נקי, מעלה ארכיון של HEAD לתיקיית staging בשרת, בונה שם, ורק אם
הבנייה וה-health checks עברו — מחליף את הגרסה החיה. אם משהו נכשל, הגרסה הקודמת
מוחזרת אוטומטית.

`deploy_live_linux.sh` גם מנפיק תעודת TLS ב-certbot לשני ה-hostnames, כותב vhost
עם הפניה מ-`dfusreuven.co.il` ל-`www`, ומוודא בסוף ש-`robots.txt` באמת פתוח
לאינדוקס ושה-API של הטופס מחזיר 200.

> **DNS:** דומיין `.co.il` חדש יכול לקחת עד 24 שעות להתפשט. שני הסקריפטים בודקים
> את זה לפני הכול ועוצרים עם קוד יציאה 3 בלי לגעת בשרת — כי הרצת certbot לפני
> שה-DNS מוכן שורפת את מכסת הניסיונות של Let's Encrypt (5 לשעה לכל hostname).
> אפשר לבדוק עם `nslookup dfusreuven.co.il`. להעלות בלי TLS בינתיים:
> `.\deploy_live.ps1 -SkipDnsCheck`

הפרמטרים ניתנים לדריסה כמשתני סביבה — למשל
`ROUTE_BASE=/print FRONTEND_PORT=3105 bash deploy_linux.sh`.

## מה צריך להחליף לפני העלייה לאוויר

הכול מרוכז ב-`src/lib/site.ts`:

| מה | מצב |
|---|---|
| טלפון | ✅ `03-5785651` — מאומת מהרישום הציבורי |
| פקס | ✅ `03-5798656` |
| כתובת | ✅ `ז'בוטינסקי 84, בני ברק` |
| שעות פתיחה | ✅ א׳–ה׳ 07:30–19:30 · ו׳ 09:00–13:00 |
| **וואטסאפ** | ⚠️ עדיין `972500000000` — **חובה להחליף** |
| **אימייל** | ⚠️ עדיין `info@dfusreuven.co.il` — לאמת שהתיבה קיימת |
| רשתות חברתיות | ⚠️ `#` |

> **וואטסאפ הוא הקריאה לפעולה המרכזית באתר** — בהדר, בסרגל התחתון במובייל, בכל עמוד
> מוצר ובטופס. `03-5785651` הוא קו נייח ולא יכול לקבל וואטסאפ, ולכן חייבים מספר נייד
> לפני העלייה לדומיין הסופי. עד אז כל כפתורי הוואטסאפ מובילים למספר לא קיים.

**שעות הפתיחה מוגדרות במקום אחד בלבד** — `SCHEDULE` בתוך `src/lib/hours.ts`. משם נגזרים
גם התצוגה בפוטר ובעמוד צור קשר, גם תג "פתוח עכשיו" בסרגל המובייל, וגם ה-JSON-LD.

בנוסף:

- **מחירים** — `priceFrom: "החל מ-₪___"` בכל מוצר ב-`src/data/catalog.ts`
- **שמות ממליצים** — `testimonials` ב-`src/data/content.ts`
- **רכז נגישות** — `___` ב-`src/app/accessibility/page.tsx`
- **מפת Google** — placeholder ב-`src/components/ContactBlock.tsx`

## תמונות

`public/images/` מכיל 18 קובצי SVG שנבנו במיוחד לאתר ומדמים צילומי מוצר (כרטיסי ביקור,
הזמנות עם פויל, אריזות, שילוט, מדבקות, מכונת דפוס ודוגמאות גימור). הם קלים מאוד ונטענים
מיידית, אבל **מומלץ להחליף אותם בצילומים אמיתיים של עבודות מבית הדפוס** — זה שדרוג המרה
משמעותי.

להחלפה: שומרים באותו שם קובץ (או מעדכנים את הנתיב ב-`catalog.ts` / `content.ts`),
שומרים על יחס גובה-רוחב דומה ומעדכנים את תיאור ה-`alt` בעברית.
